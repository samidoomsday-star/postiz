# Local candidate hardening and operational limits

Use the guarded agency binary from this branch. Upstream binaries and old activity binaries do not enforce current policy: restoring a database alone does not make an application-only downgrade safe. Keep API mutations and workers stopped during restore/upgrade, restore private original media plus `.agency-revisions`, and verify hashes, grants, original invitations, immutable decisions, dispatch states/attempts and recovery evidence before resuming. UNKNOWN/in-flight work must not become READY simply because a backup predates its receipt. Reconcile provider facts before any future production restore; no local backup can undo external publication.

Local synthetic tools never authorize live migration/email/social publication. `rehearse-migration.py` owns only uniquely named disposable databases; `restore-media.mjs` clones local synthetic state, restores bytes separately and invokes the actual compiled media eligibility check. Missing/tampered snapshots fail closed. Do not clear shared volumes or regenerate approval history.

Review sessions remain opaque, HttpOnly/Strict, expiry-bound and tied to the original invitation and current memberships. Decisions require exact Origin plus CSRF; client links use fragments removed before API requests. Staff cookie writes require trusted Origin; explicit staff/API headers and login reject a hostile browser origin. Do not accept session credentials in URLs. Revoke the original invitation/session rather than assuming a renewal revives existing approval. Invitations accept one bounded ASCII mailbox. SMTP failure cannot create a fabricated verified identity.

Provider mutations run under a request-local context that prohibits blind helper retries on ambiguous responses and removes raw SDK/body/capability details from failures. Receipt recovery still requires current permissions, immutable approval and explicit proof. Live provider SDKs and their successful forms remain unverified; OAuth/connect routes stay closed. TikTok inbox upload cannot be scheduled as publication. YouTube/private/moderated content is not independently certified publicly visible by a receipt.

See [dependency review](evidence/dependency-review.md) and [advisory table](evidence/dependency-advisories.csv) for remaining inherited/developer package exposure restrictions. Never expose Vitest UI/Vite/dev servers, optional telemetry listeners, Temporal UI or database/mail sinks outside their loopback/private boundary. Temporal and database/media backups contain customer content and historical inherited provider credentials: protect them as secrets and restrict retention/access. The agency app never offers them to a client. Review-link/code/session credentials are excluded from histories and logs; synthetic historical tokens are public fixtures, not production credentials.

## Performance rehearsal

`scripts/agency/Dockerfile.performance` pins the Node base digest and installs OpenSSL using signed Debian packages with the session CA mounted only for the build. Use writable `BUILDX_CONFIG` under `.agency` without replacing Docker credentials/proxy settings. The profile mounts this checkout and private synthetic env in a labeled, phase-owned container, constrained to **4 CPU / 6,244,000,000 memory bytes / no additional swap**. `profile-runtime.sh` starts production backend, frontend and worker and forwards shutdown. PostgreSQL/Redis/Temporal/Mailpit remain separate local Compose services, limited respectively to 1,000,000,000 / 128,000,000 / 500,000,000 / 128,000,000 memory bytes, no additional swap. Total server memory budget is exactly 8,000,000,000 bytes; all share the executor parent 4-CPU quota. Browser/load generator run outside server memory budgets and share the same CPU quota. No build runs during final measurement; record this topology with every result. Restore only the captured phase-owned resource settings after the benchmark.

`performance.mjs` creates its own agency (50 clients, 100 channels, 10 users, 10,000 immutable two-target saved revisions), never publishes, and measures 200 real scoped requests after ten warmups. All-agency, paginated-state and client-filter counts are checked, not just status 200. The distribution measures a large saved backlog, not all media/state combinations. `performance-page.mjs` measures five full authenticated navigations, loaded rows, an operable client filter and its scoped count under local Chromium conditions. Do not claim production WAN performance, a cold database, or a live-provider SLA.

Stop the labeled profile container before using the owned process supervisor; they use the same local ports. Never ask the supervisor to kill unrecorded container processes. Keep profile env, auth headers, raw SQL plans and SDK/log artifacts in ignored `.agency`; public results contain only synthetic aggregates.

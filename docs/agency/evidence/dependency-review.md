# Phase 5 dependency advisory review

Registry source: npm bulk advisory endpoint through the managed proxy, TLS and CA verification retained. `scripts/agency/advisories.mjs` intersects each advisory range with exact locked package versions. Initial raw bulk results also included advisories against unaffected versions; those are not counted as affected. Audit output is private under `.agency/results`; the public triage table records package/version/advisory IDs without runtime secrets.

Targeted updates cover V1's reachable HTTP, media, rich editor, cookies and publication transport: Next.js 16.3.8; sharp 0.35.5; multer 2.4.0; axios 1.20.0; compression 1.8.2; proxy-addr 2.0.8; ProseMirror view 1.42.3; linkify-it 5.0.2; js-cookie 3.0.6; lodash/lodash-es 4.18.1; protobufjs 7.6.5; Tiptap core 3.30.5; DOMPurify 3.4.16; form-data major-preserving patches; ws 7/8, undici 7 and grpc-js 1.14 patches. These are reviewed security fixes on the frozen upstream base, not an automatic upstream merge or an upgrade of unrelated feature SDKs.

The full monorepo lock still contains advisories in disabled inherited features and developer-only dependencies. A local RC is **not** a zero-advisory lockfile. Do not expose dev servers, test UI, legacy SDK/MCP servers, external provider OAuth or optional telemetry listeners. Re-enabling a disabled feature requires checking its dependency paths and closing applicable advisories first.

## Reachability review

- Application entry points are AgencyController, ReviewController, LOCAL login, self-information and liveness. Legacy controllers, standalone MCP transports and tools, widgets, exports, analytics, recurring/RSS/plugs and media/AI jobs remain server-disabled. Both normal principal and API-negative tests enforce this boundary.
- Rich text, media bytes and HTTP middleware are reachable: patched before integrated checks. No user-supplied JavaScript templates, ASTs, Protobuf schemas, YAML documents, worker options, route patterns, command fragments or archive contents enter V1 operations. Fixed routes and Temporal's fixed schemas remain trusted code.
- Nodemailer sends through one configured SMTP transport. Invitation recipients are one bounded canonical ASCII mailbox; display names, lists, comments and Unicode are rejected. User input cannot set raw/envelope/attachment/transport options. No OAuth2 token fetch, multiple SMTP transports or jsonTransport is enabled. Verification transport errors are replaced with a stable message. Live SMTP/TLS configuration remains separately unverified.
- Optional OpenTelemetry/Prometheus, AI/agent/LangSmith, wallet/social-inbox, FTP, image-to-PDF, SVG import and Hono/MCP servers are not part of the enabled agency runtime. Importing a package is not evidence its vulnerable operation is reachable. This determination applies to the guarded local candidate; it does not certify the original upstream product.
- CLI/build/test packages operate only on repository-owned source/configuration. CI uses `vitest run`, never a listening Vitest UI or Vite dev server; test worker arguments are fixed. Untrusted PR code must never receive production secrets. Recheck advisories and tool exposure before changing this workflow.

Security maintenance: review this table and current registry data manually before a release; patch relevant dependencies in an isolated phase branch, run frozen install, full production build, unit/API/browser checks and replay. Keep historical scan dates and limits. Never run a broad automatic `audit fix`, accept a new vulnerable range as a pass, or treat a disabled runtime feature as live verified.

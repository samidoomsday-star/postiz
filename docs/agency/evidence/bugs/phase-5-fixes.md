Harness/build failures were investigated separately: missing OpenSSL in the slim profile image; omitted frontend lifecycle file in the first empty install rehearsal; duplicate ProseMirror Slice types after patching; an intermediate SQL edit syntax error caught by real response/count assertions; a benchmark cookie incorrectly marked HttpOnly for NOT_SECURED local mode. None was counted as a passing gate or fixed by weakening its target.

P5-009 (required workflow / S2): a terminal provider exception can follow an accepted earlier side effect in the same operation. Exception class/one local part alone cannot establish a known rejection. `ApprovalService.failed` now needs a bounded positive read-only no-side-effect contract for the current receipt/attempt before writing FAILED; unavailable/false/error evidence stays UNKNOWN. Inherited live providers have no such contract. A new synthetic outcome records actual acceptance and then throws BadBody; the service-backed regression requires UNKNOWN, forbids retry and confirms only through read-only factual reconciliation, with exactly one accepted journal mutation. The original pre-update claim object has no claimedAt, so proof binds a reloaded current receipt rather than stale claim metadata. Final API/browser rerun pending.

P5-010 (required usability / S2): the two UTC instants in New York's repeated autumn 01:30 hour had identical visible local time/zone labels. The immutable UTC values were distinct, but clients could not distinguish them from the text. Review timestamps now include a short UTC offset. The future-year browser case requires GMT-4 and GMT-5, distinct DOM datetime instants, preserved Unicode content and a decision bound to the original payload hash/time. Desktop/mobile review journeys must also pass after the display change. No timezone-profile feature was added.
